## 1. Instagram Graph API — 지금 자동화 가능한 것

출처: 콘텐츠 게시 가이드 https://developers.facebook.com/docs/instagram-platform/content-publishing , 미디어 생성 레퍼런스 https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-user/media

### 1-1. 기능별 정리

| 기능 | 가능? | 파라미터 (POST `/{ig-user-id}/media`) | 메모 |
|---|---|---|---|
| 캐러셀 | ✅ **최대 20장** [공식] | `media_type=CAROUSEL`, `children=<id,id,…>` / 각 항목 `is_carousel_item=true` | 2024년부터 20장. 지금 publish.py는 2~10장으로 막혀 있음. 캐러셀은 첫 장 비율로 잘림 |
| 릴스 | ✅ [공식] | `media_type=REELS`, `video_url`, `cover_url`(표지 이미지 URL), `thumb_offset`(ms), `share_to_feed`(true/false), `audio_name`(원본 오디오 이름, 1회만 변경) | `cover_url`이 있으면 `thumb_offset` 무시 |
| 트라이얼 릴스 | ✅ [공식] | `trial_params={"graduation_strategy":"MANUAL"}` 또는 `"SS_PERFORMANCE"` | REELS만. 비팔로워에게만 먼저 노출. `SS_PERFORMANCE` = 성과 좋으면 자동 정식 전환. 수동 전환은 앱에서만 [2차: Ayrshare]. 인스타 로그인 방식에서도 되는지는 [미검증] (bundle.social은 "페이스북 로그인 연결만 됨"이라고 씀) |
| 스토리 | ✅ [공식] | `media_type=STORIES`, `image_url` 또는 `video_url` | 링크·투표·위치 스티커 불가. 멘션은 `user_tags`로 가능. `collaborators`·`alt_text` 불가 |
| 공동작업자 | ✅ [공식] | `collaborators=["username1","username2"]` (최대 3명) | 피드 이미지·릴스·캐러셀만. 상대방이 앱에서 수락해야 공동 게시가 됨 [추정: 앱 동작 기준] |
| 사용자 태그 | ✅ [공식] | `user_tags=[{"username":"x","x":0.5,"y":0.5}]` | 이미지는 x,y 필수(0~1), 스토리는 선택. 캐러셀은 각 항목 컨테이너에 |
| 위치 | ✅ [공식] | `location_id=<위치 정보가 있는 페이스북 페이지 ID>` | 캐러셀 "항목"에는 불가, 부모 컨테이너에 넣음 |
| 대체 텍스트 | ✅ **2025-03-24 추가** [공식] | `alt_text` (최대 1,000자) | 이미지·캐러셀 이미지만. 릴스·스토리 불가 |
| AI 생성 표시 | ✅ [공식] | `is_ai_generated` | 캐러셀은 부모에만 |
| 상품 태그 | ⚠️ | `product_tags` (최대 5개) | 커머스(샵) 계정·카탈로그 필요. 게시 가이드엔 "Shopping tags are not supported"라는 문구도 있어 충돌 → 뉴스 계정엔 불필요 |
| 음악 자동 추가 | ❌ | — | 라이선스 음악은 API로 못 붙임. 영상에 직접 넣은(저작권 문제없는) 음원만 가능 |
| 필터 | ❌ [공식] | — | |
| 첫 댓글 | ✅ (이미 사용 중) | POST `/{media-id}/comments` `message=` | **고정(pin)은 API 불가** → 앱에서 |
| 캡션 | ✅ | `caption` | 문서상 2,200자·해시태그 30개·멘션 20개. 단 2025-12부터 앱 쪽 해시태그 5개 제한 (publish.py가 이미 반영) — 문서 숫자와 다름 |

### 1-2. 게시 한도
- 문서 본문: **24시간 이동 창 기준 API 게시 100건** (캐러셀 = 1건). 같은 페이지 다른 부분엔 "50건"이라는 문구가 남아 있음 → **충돌**. [공식, 서로 다름]
- 실제 숫자는 `GET /{ig-user-id}/content_publishing_limit?fields=config,quota_usage`로 확인 (publish.py가 이미 함, 기본값 50으로 가정 중 → 안전한 쪽).
- 하루 1~5건 올리는 운영이면 어느 쪽이든 문제없음.

### 1-3. 통계(Insights) — `GET /{media-id}/insights?metric=...`
출처: https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-media/insights

| 구분 | 지표 |
|---|---|
| 공통 | `reach`, `views`, `likes`, `comments`, `saved`, `shares`, `total_interactions`, `profile_visits`, `profile_activity`, `follows`, `reposts` |
| 릴스 | `ig_reels_avg_watch_time`, `ig_reels_video_view_total_time`, `reels_skip_rate` |
| 스토리 | `navigation`, `replies`, `link_clicks` (24시간만 조회 가능 → `story_insights` 웹훅 권장) |
| 폐지 | `impressions` (2024-07-02 이후 게시물), `plays` → `views`로 대체 |

- 권한: 인스타 로그인 = `instagram_business_manage_insights` / 페이스북·통합 로그인 = `instagram_manage_insights`.
- 값이 5 미만이면 오류(code 10) 나는 지표 있음.

### 1-4. 댓글 웹훅 · DM 자동화 (ManyChat 같은 "댓글 키워드 → DM")
- **공식 기능 있음: Private Replies** [공식] https://developers.facebook.com/docs/instagram-platform/private-replies
  - `POST /{ig-user-id}/messages` 본문 `{"recipient":{"comment_id":"<댓글ID>"},"message":{"text":"..."}}`
  - 댓글 1개당 **DM 1통만**, 댓글 작성 후 **7일 이내**. 상대가 답장하면 그때부터 24시간 대화 가능.
  - 키워드 감지는 **웹훅(`comments` 필드)** 으로 받아야 함 → 항상 켜진 HTTPS 서버 필요 (GitHub Actions 크론으로는 실시간 불가. 대신 30분마다 댓글 목록을 조회해 답장하는 "폴링" 방식은 가능 [추정]).
  - 권한: 인스타 로그인 기준 `instagram_business_manage_comments` (+ 메시지 권한, 문서가 애매) [미검증]. 남의 계정이 아닌 **내 계정만** 쓰는 개발 모드 앱이면 심사 없이 될 가능성 높음 [추정].
  - 한도: 시간당 750건 private reply [2차, 여러 업체 블로그 일치].
- ManyChat 등은 Meta 공식 파트너라 정책상 허용. 단 `HUMAN_AGENT` 태그를 봇 메시지에 쓰는 건 금지 [2차].
- **결론:** 뉴스 계정 초반엔 불필요. 팔로워 1천 넘으면 "댓글에 KAYNAK 쓰면 출처 링크 DM" 같은 흐름으로 고려.

| **YouTube Shorts** | `videos.insert` (Data API v3) | 무료 | 업로드 1회 = 별도 버킷 하루 100회 [공식]. **2020-07-28 이후 만든 미인증 프로젝트는 업로드가 비공개로 잠김**, 감사(audit) 통과해야 공개 [공식 문구, 2차 인용] | ❌ 자동화는 감사 필요. YouTube Studio 수동 예약은 무료 |
| **X (트위터)** | `POST /2/tweets` | 2026-02-06부터 **종량제**, 무료 등급 사실상 종료 [2차 다수] | 게시 1건 약 $0.01, 링크 포함 글은 더 비쌈 [2차, 금액 미검증] | 🔶 하루 2건이면 월 1달러 안팎 [추정]. 터키 X 사용자층은 큼 → 나중에 검토 |

## 4. publish.py 개선안 (수정은 하지 않음 — 설계만)

현재 구조: `posts.json` + `posts/<id>/` + `state.json`, `Api.publish_carousel()`, `IG_API_HOST=graph.facebook.com`, 시스템 사용자 토큰.

### (a) 계정 여러 개 + 토큰 분리
- 폴더 구조: 계정별로 저장소를 따로 두거나(가장 단순, 지금 코드 그대로 복사), 한 저장소에 `accounts/<account>/posts.json`, `accounts/<account>/state.json`으로 분리.
- 환경변수: `IG_USER_ID_TR`, `IG_ACCESS_TOKEN_TR`, `IG_USER_ID_ES`, … 를 GitHub Secrets에 등록하고 `--account tr` 인자로 고름.
- `Api.__init__(self, account)`에서 `os.environ[f"IG_USER_ID_{account.upper()}"]` 읽기.
- 시간대: TR은 `+03:00`, ES 계정이 스페인 대상이면 `+01:00`(겨울)/`+02:00`(여름) — 현재 고정 오프셋 방식이라 **서머타임 처리 안 됨** → `zoneinfo("Europe/Madrid")` 사용 권장. 중남미 대상이면 시간대 다시 결정.
- 같은 비즈니스 포트폴리오의 시스템 사용자에 두 인스타 계정을 모두 할당하면 **토큰 1개로 둘 다** 될 수 있음 [미검증] — 그래도 사고 격리를 위해 계정별 시크릿 권장.
- `state.json` 동시 쓰기 충돌 방지: 계정별 파일 + 워크플로 `concurrency` 그룹 계정별로.

### (b) 릴스 업로드
```
POST /{ig-user-id}/media
  media_type=REELS
  video_url=https://…/reel.mp4
  cover_url=https://…/cover.jpg      (선택)
  share_to_feed=true                 (선택)
  caption=…
  collaborators=["…"]                (선택)
  trial_params={"graduation_strategy":"SS_PERFORMANCE"}   (트라이얼일 때만)
→ GET /{container}?fields=status_code   (FINISHED까지 대기, 영상은 수 분 걸림 → 지금 wait_ready 30×5초=2.5분은 짧을 수 있음, 늘릴 것)
→ POST /{ig-user-id}/media_publish creation_id=…
```
- **GitHub raw URL로 영상 되나?** 직접 확인 결과 raw.githubusercontent.com은 mp4를 `Content-Type: application/octet-stream`으로 줌. 이미지는 지금 잘 되고 있으니 Meta가 형식을 파일 내용으로 판단할 가능성이 있지만, 영상은 **[미검증]** — 실패 시 오류 2207026(형식)/2207052(가져오기 실패).
  - 안전한 대안: **GitHub Pages**(`video/mp4`로 정상 제공, 무료) 또는 Cloudflare R2 등.
  - 저장소 파일 100MB 제한, 공개 저장소라 게시 전 영상 노출됨(지금 이미지와 동일).
- 대안: 재개형 업로드 `upload_type=resumable` → `https://rupload.facebook.com/ig-api-upload/<버전>/<컨테이너ID>`에 파일 직접 전송(로컬 파일 가능). 문서상 **"Facebook Login for Business 앱만"** → 지금 시스템 사용자 토큰 구성에서 되는지 [미검증].
- 영상 규격: MP4/MOV, H.264 + AAC, 9:16 권장 [공식 일반 규격].
- 카드 → 영상 변환: ffmpeg로 카드 이미지 슬라이드쇼(장당 2~3초) 만들기 [추정, 쉬움].

### (c) 스토리
```
POST /{ig-user-id}/media  media_type=STORIES  image_url=https://…/story.jpg
→ wait_ready → POST media_publish
```
- 1080×1920(9:16) 이미지 따로 만들 것. 4:5 카드를 그대로 올리면 위아래 여백 [추정].
- 링크 스티커 불가 → "새 게시물 보러 가기" 문구만. 피드 게시물 공유 스티커도 API 불가 [추정].
- 게시 한도에 스토리도 포함되는지 [미검증].

### (d) 공동작업자
- `publish_carousel()`의 **부모(CAROUSEL) 컨테이너** 생성 시 `collaborators=json.dumps(["koreli.mom"])` 추가.
- `posts.json` 항목에 `"collaborators": [...]` 필드 추가하는 방식 권장. 최대 3명, 스토리 불가.
- 상대가 수락 안 하면 내 계정에만 보임 [추정].

### (e) Threads 교차 게시
1. 앱에 **Threads 사용 사례** 추가 → 본인을 "Threads Tester"로 등록 → 승인 → 인증 코드 → 단기 토큰 → **장기 토큰(60일)**. 권한 `threads_basic`, `threads_content_publish`. 출처: https://developers.facebook.com/docs/threads/get-started
2. 게시:
```
# 각 이미지
POST https://graph.threads.net/v1.0/{threads-user-id}/threads
  media_type=IMAGE  image_url=…  is_carousel_item=true
# 묶기
POST …/{threads-user-id}/threads  media_type=CAROUSEL  children=id1,id2,…  text=(500자 이하)  topic_tag=KoreaNews
# 발행 (문서: 컨테이너 생성 후 평균 30초 대기 권장)
POST …/{threads-user-id}/threads_publish  creation_id=…
```
   출처: https://developers.facebook.com/docs/threads/posts
3. 주의: 인스타 캡션(최대 2,200자)은 Threads 500자 초과 → **`threads.txt` 별도 작성**. 해시태그는 1개(`topic_tag`)만 의미 있음.
4. 토큰 갱신: `GET https://graph.threads.net/refresh_access_token?grant_type=th_refresh_token&access_token=…` 를 60일 안에. GitHub Secret을 워크플로가 스스로 바꾸려면 별도 PAT 필요 → **달력 알림으로 수동 갱신**이 단순 [추정].
5. 사용량: `GET /{threads-user-id}/threads_publishing_limit`.
6. 실패해도 인스타 게시는 되돌리지 않도록 `after_publish`처럼 try/except로 분리, `state.json`에 `threads_id` 따로 기록.

### 기타 작은 수정
- 캐러셀 장수 검사 `2 <= n <= 10` → `<= 20`.
- 모든 이미지에 `alt_text` 추가 (`alt.txt` 한 줄씩) — 접근성 + 검색 신호 [추정].
- 통계 수집 시 `impressions` 대신 `views`, `reach`, `saved`, `shares` 사용.

### 새 계정 워밍업 (전부 **[추정/업계 통념]**, Meta 공식 가이드 없음)
1. 계정 생성 직후 며칠은 **사람이 앱으로** 프로필 완성(사진·바이오·이름), 관련 계정 몇 개 팔로우, 스토리 1~2개.
2. 프로페셔널 전환 → API 연결은 그 다음. 첫 주는 하루 1건.
3. 같은 IP·기기에서 계정 여러 개 운영 자체는 인스타가 공식 허용(최대 5개 전환) — 하지만 같은 행동을 동시에 반복하지 말 것.
4. 게시 시각을 매일 정확히 같은 분에 맞추는 게 문제라는 근거는 없음 [미검증] — 그래도 몇 분 랜덤 지연 넣는 건 손해 없음.
5. 갑자기 팔로우·좋아요 대량 행동 금지 (이건 API로도 불가능).

## 6. 추천 실행 순서
1. TR·ES 계정 각각 저장소(또는 계정별 폴더) + 시크릿 분리 → 캐러셀 자동화 시작 (지금 코드 거의 그대로).
2. 캐러셀 상한 20장, `alt_text` 추가.
3. Threads 교차 게시 추가 (무료·쉬움·심사 불필요).
4. 표지 9:16 이미지로 스토리 자동 게시.
5. ffmpeg 슬라이드 영상 → 릴스 (GitHub Pages에 영상 두고 시험) → 트라이얼 릴스 실험.
6. TikTok·Shorts는 같은 영상으로 **앱에서 수동/네이티브 예약**.
7. 팔로워 생기면 댓글→DM(Private Replies), 통계 수집.
